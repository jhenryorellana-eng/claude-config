# Persistent Memory for code-reviewer

_This file is loaded at the start of each invocation. Keep entries concise. Lines after 200 are truncated._

## Patterns learned

### Astro + CDN globals pattern (observed in olivar-landing)
- When GSAP/Lenis/SplitType are loaded via CDN `is:inline` scripts, component `<script>` blocks that import from local lib files must use a `waitForGlobal()` polling pattern to avoid race conditions. Polling with `setTimeout` (50ms, 60 retries) is the established pattern in this codebase.
- Astro bundles `<script>` (no directive) separately from `is:inline`. Imports from local TS lib files work inside bundled scripts; they do NOT have access to CDN globals at module parse time — only at runtime, hence the polling approach.

### `scroll-behavior: smooth` + Lenis conflict
- `scroll-behavior: smooth` on `html` element causes ScrollTrigger refresh/pin bugs in some browsers. The correct fix is to override it to `auto` via `.lenis.lenis-smooth { scroll-behavior: auto !important; }`, which this codebase already does. Flag if ever removed.

### `will-change` in global CSS — known performance smell
- Applying `will-change: transform` statically in CSS on `.split-char`, `.char`, `.tilt-card`, `.marquee__track` promotes ALL those elements to GPU layers at paint time, even before animation. For landing pages with many splits, this can cause excessive GPU memory. The pattern to prefer: set `will-change` dynamically in JS right before animating, remove in `onComplete`. The motion.ts library in this codebase does this correctly; the global.css declarations are redundant and slightly wasteful.

### SplitType + GSAP `yPercent` trick
- Wrapping parent element needs `overflow: hidden` on the `.split-word`/`.word` class for the "slide up from below" effect. global.css correctly sets this. If ever removed, the character animation leaks outside its container.

### Timezone-safe date parsing
- `new Date('YYYY-MM-DD')` parses as UTC midnight, which in timezones behind UTC (like AR, UTC-3) renders as the previous calendar day when formatted with locale-aware APIs. Appending `T00:00:00` (local) fixes this. The whatsapp.ts implementation uses this pattern correctly.

### og:type "restaurant" is non-standard
- The Open Graph protocol does not define a "restaurant" type. Valid values include "website", "article", etc. Using "restaurant" is harmless (falls back to "website" in most parsers) but technically incorrect per OGP spec.

### Marquee `data-dir` attribute referenced but never set
- Layout.astro's `initMarqueeVelocity()` reads `track.dataset.dir` to determine direction, but Marquee.astro never sets that attribute. All tracks will always go left. Harmless visually (single direction is fine) but the reverse-direction feature is silently dead.

### GSAP ScrollTrigger cleanup in Astro (SPA concern)
- In a static Astro site (output: static), there is no client-side routing by default, so ScrollTrigger instances persist for the full page lifetime — cleanup is not necessary. If View Transitions are ever added, all ScrollTrigger instances must be killed and Lenis destroyed in the `astro:before-swap` event.

### henryflow: applyExtractedCartaValues double-call in new_address worker
- The new_address worker calls `applyExtractedCartaValues` twice: once for address fields, once for court fields. Between the two calls the carta row's `updated_at` advances, so the second call does a fresh read and compares against the new timestamp. ### usalatino-v2: Supabase getClaims() + app_metadata split (reviewed 2026-06-12)
- When the Custom Access Token Hook injects `{org_id, user_kind, user_role}` as TOP-LEVEL JWT claims, `app_metadata` inside the JWT is NOT automatically populated. `getClaims()` returns the full JWT payload (hook claims at top level). `getUser()` returns a user object where those claims may appear at top level OR merged into `app_metadata` depending on supabase-js version.
- Fields stored directly by the admin API in `auth.users.app_metadata` (e.g. `must_change_password`) do NOT appear as top-level JWT claims unless the hook explicitly re-reads and injects them. Always add hook-managed app_metadata fields explicitly to the hook output if needed in middleware.
- Pattern: middleware that uses `getClaims()` for the fast path must account for fields that only exist in `app_metadata` (not in hook claims) separately. Either inject them via hook, or fall back to `getUser()` for staff routes.

### usalatino-v2: multi-tier upstash rate limit — use sequential not parallel (reviewed 2026-06-12)
- Checking multiple Ratelimit tiers with `Promise.all` decrements ALL counters regardless of which tier denies. This silently burns hourly/daily quotas during burst-denied requests. Correct pattern: check sequentially and return on first denial. The latency difference is negligible when a floor timer is already in place.

### usalatino-v2: console.error bypasses structured logger (recurring smell)
- Any `console.error/log/warn` in server-side code bypasses the project's PII redaction in `platform/logger.ts`. Flag any non-logger stdout writes in actions.ts, service.ts, or repository.ts. The correct replacement is always `logger.error({ err }, "message")`.

### usalatino-v2: events.ts fire-and-forget async consumers
- `EventBus.emit()` uses `void handler(event)` — synchronous throws are caught but async rejections after the first await are not. Pattern to fix: attach `.catch()` to the returned promise. This will bite on the first real async consumer (F1+).

### usalatino-v2: updateEmployeePermissions / deactivateEmployee missing self-guard (F1 — reviewed 2026-06-12)
- Neither `updateEmployeePermissions` nor `deactivateEmployee` check `actor.userId === staffId`. The spec (DOC-22 §9.3) explicitly says "no a sí mismo". A non-admin staff with employees.edit (hypothetical) could deactivate their own account or escalate their own permissions. The fix is a one-line guard at the top of each use case: `if (actor.userId === staffId) throw new AuthzError('forbidden_module')`.
- `deactivateEmployee` also has no org ownership check on `staffId` — a staff member from a different org could be targeted if multi-tenancy is ever enabled. Pattern: always verify the target user belongs to `actor.orgId` before operating.

### usalatino-v2: CSV formula injection — csvEscape only quotes, never strips formula prefix (F1)
- The `csvEscape` function in `audit/service.ts` only adds RFC 4180 quoting (for commas/newlines/quotes). It does NOT neutralize formula-trigger characters (=, +, -, @) at the start of a cell value. Audit log fields (action, entity_type, entity_id, diff) are system-generated so risk is currently very low, but `diff` is a JSON blob of user-supplied data — if an org.name contains `=cmd()` it will appear unescaped in the exported CSV. Add prefix sanitization: if `s.startsWith('=') || s.startsWith('+') || s.startsWith('-') || s.startsWith('@')`, prepend a single tab or quote-wrap with a leading apostrophe.

### usalatino-v2: approveFormResponse / generateFilledPdf — missing requireCaseAccess (F4-Ola3, reviewed 2026-06-14)
- Both `approveFormResponse` and `generateFilledPdf` accept a bare `responseId` (no `caseId` in input). They use `can(actor, "cases", "edit")` which checks staff permission but NOT org ownership of the case. The serviceClient `findFormResponseById` is RLS-bypassing, so a staff member from org A could theoretically approve/generate PDF for a response belonging to org B if they know the responseId UUID (service_client bypasses RLS). Fix: after loading the response, call `requireCaseAccess(actor, response.case_id)` (which calls `can()` for staff, enforcing org_id scoping via the staff's org from their JWT). The DB-level trigger `enforce_form_response_approval` is a secondary guard but not a substitute for service-layer org check.
- This is the same vulnerability pattern as `reviewDocument` and `deactivateEmployee` reviewed in F1.

### usalatino-v2: validateAnswerTypes — select field values not validated against options whitelist (F4-Ola3)
- `validateAnswerTypes` in `domain.ts` validates required, regex, min, max. For `field_type='select'` it does NOT verify that the submitted value is one of the `options[].value` items. A client could save any string. The client Zod schema also lacks this (`buildQuestionSchema` treats select as a plain string). Mitigation: add an `options` check in `validateAnswerTypes` when `q.field_type === 'select' && q.options?.length > 0`.

### usalatino-v2: mergeFormAnswers — read-then-write race window (F4-Ola3)
- `mergeFormAnswers` does a SELECT then UPDATE in two separate statements. Two concurrent autosave calls can race: both read the same snapshot, one overwrites the other's merge. The spec says "last-write-wins per field" (RF-DIA-023 CA2). Fix: use a Supabase RPC with `jsonb_merge_patch` or a SQL `UPDATE ... SET answers = answers || $patch` to make the merge atomic. The current approach is safe in practice only when saves are serialized (the `inFlightRef` in `useAutosave` serializes within a tab, but multi-tab or multi-device use is not protected).

### usalatino-v2: isReadOnly includes 'in_validation' status (F4-Ola3)
- `resolve.ts isReadOnly()` treats `in_validation` as read-only. However `FormResponseStatus` in `domain.ts` only has `draft | submitted | approved` — `in_validation` is a `CaseStatus`, not a `FormResponseStatus`. It appears this was added defensively (a form cannot be submitted if the case is in_validation). The DB constraint on `case_form_responses.status` is `('draft', 'submitted', 'approved')` — the form_response will never actually have `in_validation`. This is dead code but not harmful. Flag for cleanup.

### usalatino-v2: AI stub / QStash bypass seam — security architecture (F4-Ola4, reviewed 2026-06-15)
- `isAiStubEnabled()` in `ai-stub.ts` is the single gate: returns false unless `AI_E2E_STUB==='1'`, throws (fail-loud) if that flag is set in `NODE_ENV==='production'`. This means the stub and the QStash bypass are structurally impossible in production (not just env-convention — they hard-throw on first call to that function from any code path).
- The QStash bypass in `verifyQStashSignature` requires BOTH `isAiStubEnabled()` AND `x-e2e-qstash-bypass: 1` header. The header alone does nothing — `isAiStubEnabled()` is checked first. In prod the throw happens before the header is ever read. A real QStash delivery in dev (no bypass header) still goes through full `Receiver.verify()`.
- `SUPABASE_SERVICE_ROLE_KEY` in `e2e/helpers/db.ts` is read from `process.env` inside the Playwright runner process only. `playwright.config.ts` loads it via `@next/env loadEnvConfig()` into the runner's process — it is never referenced in any `NEXT_PUBLIC_*` variable and therefore never bundled into the client JS. The risk of it leaking to the browser bundle is zero given the current variable names. The real mitigation to keep: ensure `.env.local` is in `.gitignore` and is not committed.
- The `dev:e2e` script (`cross-env AI_E2E_STUB=1 next dev`) sets the stub flag only in the Next.js server process. The Playwright runner is a separate process and does NOT inherit AI_E2E_STUB. This is correct and expected — the runner reads service-role key, not the AI stub flag.
- ai-stub.test.ts: the "is true in non-production" test stubs NODE_ENV to 'test' explicitly. This is important because Vitest itself sets NODE_ENV='test', so the implicit value works, but the explicit stub makes it unambiguous. Pattern is correct.
- The segmentation stub in `ai-stub.ts buildStubSegmentation` regex `^- (\S+) \([a-z]+, page \d+\)` uses `\S+` (greedy, no dot) to capture the field name — this is correct since AcroForm field names contain alphanumerics, underscores, and dots but no spaces.
- Monthly-close test in ai-budget-aggregation.test.ts uses `setUTCMonth(getUTCMonth() - 1)` without a UTC-day guard. If today is January 31 and previous month is February, `setUTCMonth(-1+1=0)` → Feb 31 → rolls to Mar 3. This is a latent bug in test date logic but does not affect production (the real job runs on the last day of the month, not January 31 specifically). Low risk but worth noting.

### usalatino-v2: Business Calendar unification — patterns and gotchas (reviewed 2026-06-15)

#### assertWithinBusinessHours — boundary semantics
- Uses `localHour < b.end_hour` (exclusive upper bound), consistent with `getAvailableSlots` which does `for (let hour = start_hour; hour < end_hour; hour++)`. A 9:00-12:00 block allows 9:00, 10:00, 11:00 but NOT 12:00. Correct — do not change to `<=`.
- Checks `localHour >= b.start_hour` — inclusive lower. Combined: [start, end). Matches slot generator.
- Punctual block overlap uses `ts < end && apptEnd > start` — standard interval overlap test. Correct.

#### resolveConsultantIds — 2 DB round-trips by design
- First query: get all profiles where role=employee AND employee_type=senior_consultant.
- Second query: filter those IDs by presence in consultant_availability.
- This intentionally excludes senior_consultants who have no agenda yet. Expected pattern.

#### assertWithinBusinessHours called AFTER validateClientBooking in reschedule path
- `validateReschedule` (book-service.ts) now calls `assertWithinBusinessHours` internally.
- The reschedule endpoints that call `validateReschedule` do NOT need a separate `assertWithinBusinessHours` call — it's included. Checked: employee/appointments/reschedule calls only `validateReschedule`, not assertWithinBusinessHours separately. Correct.

#### Double loadBusinessSchedule in admin/employee book flows
- In /api/employee/appointments/book (non-guest path): `validateClientBooking` does NOT call `assertWithinBusinessHours`. The explicit call to `assertWithinBusinessHours` right after is needed. No duplication.
- In /api/admin/appointments/book (non-guest path): same pattern. Correct.
- `assertWithinBusinessHours` triggers `loadBusinessSchedule` once. `resolvePrimaryConsultantId` triggers `resolveConsultantIds` then another query to consultant_availability. In book flows: both assertWithinBusinessHours AND resolvePrimaryConsultantId are called → 3 extra DB queries. Minor but acceptable for write paths.

#### source field removed from voice-agent/slots response
- The Gemini client (voice-call.tsx) passes the entire JSON blob back to the model via `safeSendToolResponse`. It never cherry-picks `result.source`. Removing `source` from the response is safe.

#### prospect_scheduling_* tables — now orphaned (readers removed)
- All callers now read from business-calendar. The tables still exist in the DB and `/api/admin/prospect-scheduling` still writes to them. The admin UI for prospect scheduling config is now a dead write (no reader). Flag if admin wants to repurpose that UI to write consultant_availability instead.

#### getAvailableSlots slot step is 1 hour (integer)
- `for (let hour = start_hour; hour < end_hour; hour++)` increments by 1 integer hour. If `slotDuration` is 30 minutes, two slots per hour are NOT generated — only one per integer hour. This was existing behavior, not introduced by this PR. But with 60-minute default for prospects (new behavior), it's correct.

#### mtToUTC in slots.ts — known DST bug (pre-existing, not introduced here)
- `mtToUTC` builds a UTC date from Intl parts as `new Date('YYYY-MM-DDThh:mm:ssZ')` — treating the Intl output as UTC to compute offset. This rounds correctly for DST because Intl is called on `tempDate` which is the slot in UTC, giving the correct MT offset at that instant. Then adds offsetMs to the target. Valid pattern.

### usalatino-v2: seedBoardColumns swallows 23505 at batch level — correct but lossy (F5-Ola3)

### usalatino-v2: applyPaymentSuccess — crash-safe ledger order (F6-Ola1, resolved)

### usalatino-v2: Stripe checkout TOCTOU — DB-as-mutex pattern (F6-Ola1, resolved)

### usalatino-v2: translateMessage — findMessageById before requireParticipant (F7-Ola7a, STRONG)
- `translateMessage` calls `findMessageById(messageId)` (service-role, bypasses RLS) BEFORE `requireParticipant`. A valid authenticated user (of a different conversation) who guesses a messageId UUID can call `translateMessageAction` and trigger AI translation of a message they're not entitled to read. The translated text is NOT returned to them (requireParticipant throws before return), but the AI call still executes and writes `body_translated` to the message. ### usalatino-v2: "omit-when-untouched" upsert contract silently defeated by a non-optional VM field always sending the key (Carátula de Envío / mailing_cover feature, reviewed 2026-07-22, BLOCKER class — reusable pattern)

Once the migration IS applied, this specific instance causes no data loss (the state always round-trips the currently-loaded value for the ONE config that legitimately uses it), but the code's own comment ("Omit to preserve the stored value") is misleading/effectively dead code from this UI.
- **General pattern to check on every future "config-as-data, nullable, admin-editable" column added to a config editor already used for MANY unrelated rows**: if the new field is wired into a shared editor's state as `field: T | null` (required, not `field?: T | null`) and the save handler does a plain object-literal spread (`{ ...allFields, field: state.field }`), the "send only when touched" contract at the backend is unreachable from that UI.
